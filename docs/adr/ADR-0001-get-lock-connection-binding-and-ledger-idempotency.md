# ADR-0001：GET_LOCK 会话级锁的连接绑定与账本幂等模型

| | |
|---|---|
| 状态 | Accepted |
| 日期 | 2026-10-15 |
| 关联 | 设计文档 §6.5（provisioning 执行模型）、§14 R1-P0② |

## 背景（Context）

租户供给（provisioning）把幂等当作第一设计约束：种子脚本集合可能被两个实例并发执行
（多副本部署、人工重试、定时任务兜底都可能触发）。MySQL 侧的自然工具是 `GET_LOCK`，
但它有一个关键语义：**GET_LOCK 是会话级锁，不是事务锁**——锁的生命周期绑定在获取它的
那条**物理连接**上，与事务边界、线程边界都无关。

把它与 HikariCP 这类连接池组合时，存在两类经典事故（生产实证，缺一层规格就踩一次）：

1. **跨连接持锁 = 锁形同虚设**。在池借出的连接 A 上 `GET_LOCK`，随后执行种子脚本时
   `TransactionTemplate` 又从池里借出连接 B——锁挂在 A 上，真正干活的是 B。第二个实例
   同样「A' 持锁、B' 干活」，两把锁互不可见，互斥完全失效，同一租户被并发供给。
2. **同连接忘释放 = 锁泄漏**。持锁连接被归还连接池后，会话仍存活、锁仍被持有。此后该
   租户的任何供给请求 `GET_LOCK` 永久等待直至超时——线上表现即「上线三个月后该租户供给
   永久失败无出路」。

此外，仅靠锁不足以保证幂等：进程崩溃、锁超时后的重复执行，都需要一份持久化的
「哪些脚本已对哪些租户执行过」账本；而账本在并发插入时自身也会撞唯一键，这一撞的
语义必须事先定义。

## 决策（Decision）

规格三层，缺一不可：

1. **单条专用物理连接全程持锁**。通过 `ConnectionCallback` 路径借出一条专用连接，
   在其上执行 `GET_LOCK("tenantkit:provision:<tenant>", timeout)`；随后**逐脚本**用
   `TransactionTemplate` 在各自独立连接上执行（脚本事务与锁连接解耦，但持锁连接本身
   全程不出借、不归还）；结束时**在持锁连接上** `RELEASE_LOCK`，最后才归还连接。
   锁超时按 `tenantkit.provisioning.lock-timeout-seconds` 配置抛错或等待，语义写入
   配置元数据。
2. **账本幂等双保险**。账本表 `tenantkit_seed_history` 带 `UNIQUE KEY
   (tenant_id, script_name)`；执行前逐脚本比对 checksum（SHA-256，换行 CRLF/LF
   归一化，文件名参与计算）：一致 → 跳过；**不一致 → 硬拒放**
   （`TenantProvisioningException`，TK-2xxx 族）——禁止静默重放改过 checksum 的脚本，
   那等于改写历史。并发插入撞 `DuplicateKey` 视为**幂等成功**：
   `ProvisionReport.duplicateKeyShortCircuit = true`，语义是「另一实例已记账」，
   不是失败。
3. **finally 释放锁**。取锁、执行、释放同处一个 try/finally 块；无论成功、脚本失败、
   超时还是中断，持锁连接上的 `RELEASE_LOCK` 必达，配套用例断言异常路径锁不泄漏。

配套语义一并列死：

- 单脚本 = 单事务；`${tenantId}` 占位符替换在默认字符集 `[a-z0-9-]` 下无注入面；
  **放宽 `tenant-id-pattern` 的指引必须绑定警告**：占位符替换同步改为参数化或白名单
  转义，否则重新打开注入面。
- 任一脚本失败 → 该租户供给整体失败，账本现状保留（已成功脚本不回滚、不重放）。
- **修复路径**：种子脚本合法修订导致 checksum 不一致时，`provision --repair` 显式
  确认后重录 checksum，并输出审计 diff——杜绝「永久供给失败无出路」。
- 账本表是**全局表**，未来任何行级过滤器（v1.x 路线图）的豁免名单必须包含它
  （纪律详见 ADR-0002）；账本表迁移脚本由应用自己的 Flyway/Liquibase 执行，
  kit 不内嵌迁移引擎。

## 后果（Consequences）

- **正面**：互斥真实成立（锁连接与执行连接物理分离且归属明确）；崩溃与并发双场景
  幂等；异常路径锁不泄漏有测试断言兜底；改历史必须走显式 `--repair` 并留审计痕迹。
- **代价**：供给期间占住一条池外专用连接（文档写清对连接池容量的影响）；用户放宽
  TenantId 字符集时必须同步加固占位符替换，不能只改 regex。
- **砍线说明**：两线程同抢同一把 GET_LOCK 的并发竞争容器用例按 §11 滑 0.1.1
  （issue 挂名登记，不静默消失）；v0.1 以等价单测覆盖策略分支。
